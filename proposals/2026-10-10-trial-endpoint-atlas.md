# A trial endpoint atlas: what cystic fibrosis trials register as their main outcome

Status: proposed, written 2026-10-10. The offline tools for build step 1 are in a separate pull request (#35) and have never run against the real registry; nothing else is built. Untested design.
Provenance: drafted by `claude-sonnet-5-5` after two independent reviews of one design packet, one `claude-opus-5-5` for method and usefulness and one `claude-sonnet-5-5` for product, design and accessibility (their findings were leads; the controller checked what it could against the catalog, the evidence skill's provider code and the registry's own pages). No local model and no Fable were used for this proposal. The ClinicalTrials.gov pages quoted below were rendered once each on 2026-10-10 with a browser and an honest, project-named user agent after reading the site's robots.txt, which does not disallow the documentation pages (`/data-api/`) or the terms page. It does disallow `/api/` for crawlers, which is the path the fetch tool will use; the catalog records that the published API terms govern that access instead, so robots.txt is not permission for the fetch. A second blind review (claims, compliance and voice) corrected this text on 2026-10-10. Claims marked "from memory" were not checked.

## What is asked

One flagship piece for researchers and clinicians (and readable by people living with CF and their families): an atlas of what interventional CF trials register as their primary outcome measures, from one dated, hashed snapshot of ClinicalTrials.gov, with the exact registry words behind every number. It is meant to show what the lab's method does: deterministic code, a local worker held to exact quotes, a blind reviewer from a different family, and a set labelled by a person before any model runs.

## Decisions made in this design (and why)

1. **Count unit.** The headline unit is the study (counted once per class); the unit that is tagged is the outcome entry (measure, description, time frame). Charts say which unit they use and never mix them. A study can name several classes, so class totals exceed the study total, and every figure says so.
2. **Date axis.** Study start year (planned dates marked as planned), with the first-posted year used only to band the registration eras. Registered text is today's text, so every trend caption says "current registered wording; earlier versions may differ".
3. **Scope.** Interventional studies whose condition list names CF, all statuses and dates. Expanded access and observational studies are out. Each study is flagged "CF only" or "CF among others". A second retrieval route (a term search with CF spellings) is run and the difference printed, with a hand check of 20. Explicit exclusions (for example non-CF bronchiectasis) are listed with their count. Stated plainly: one registry, one query, one date.
4. **Taxonomy.** Two levels. Domains and classes: pulmonary function (FEV1, other spirometry, lung clearance index, lung function unspecified); CFTR function (sweat chloride, nasal potential difference, intestinal current, other biomarker); exacerbations; nutrition and growth; GI and pancreatic; glucose and CF-related diabetes; liver; sinus and upper airway; patient-reported (CFQ-R, other named instrument, unnamed); imaging; microbiology and sputum; inflammation markers; healthcare use; survival and transplant; safety and tolerability (with a subtype); pharmacokinetics; feasibility and adherence; exercise capacity (six-minute walk, peak oxygen uptake; added 2026-10-10 after the build review, to be confirmed by the maintainer before the frozen set is labelled); other; not stated. Vague wording ("lung function", "efficacy") is never inferred to FEV1; its share is reported as a finding. Composite outcomes carry a flag and the component classes. A versioned rule lexicon runs first; a model may propose a class only for the remainder and must quote the registry text exactly; a script rejects any quote that is not an exact substring; every tag records whether a rule or a model made it.
5. **Validation.** A person labels 50 outcome entries before anyone sees a rule or a model result: a stratified sample (start decade by phase), with rare classes and lexicon-unclassifiable entries oversampled; those rows stay out of rule development and may be extended to 150. The person relabels 20 two weeks later. Printed: per-class precision and recall with the number of checked rows and a Wilson 95% interval (not estimated where fewer than 10 positives; the page says "few checked"), micro and macro F1, the share tagged by rule, by model, as other and as not stated, the model quote-rejection rate and the challenger disagreement rate. Publication stops if any class shown has precision below 0.85 or recall below 0.80 on the frozen set, "other" exceeds 15% of entries, the two retrieval routes differ by more than 10% unexplained, a negative control fails, or a rerun on the same snapshot does not reproduce the counts and the hash. These thresholds are the reviewer's judgement, not a standard; the maintainer can change them before the frozen set is labelled and not after. Negative controls: tag a matched asthma or COPD snapshot (CF-specific classes must come out near zero), plant model tags whose quotes are not substrings (all must be rejected), and plant known non-CF NCT ids (scope must exclude all).
6. **A front door, not a dashboard.** The main page carries aggregates only. Every count links to a static page per class that shows the exact registry wording, with the matched span marked (an underline as well as a highlight), the NCT id as a link to the registry, and whether a rule or a model tagged it. Registry quotes carry `lang="en"`. The trial-level CSV sits outside the page-weight budget.
7. **What the registry's terms require, and how the design meets each.** The terms apply to "any publication or distribution", so the same items go on the page AND on every download (the trial-level CSV, the counts CSV, any committed snapshot, the manifest): (a) the source named as ClinicalTrials.gov, with a link; (b) the date the registry processed the data (the `dataTimestamp` at snapshot time), and the snapshot date and hash; (c) a plain, complete description of every modification the lab made (the sorting of outcome wording into classes, the exclusions, the clipping of long wording, the re-saving of each page after parsing); (d) a statement that the lab's licence covers only the lab's own tags, code and counts, and that registry text and fields remain ClinicalTrials.gov data under its Terms and Conditions (the research repository is under CC BY 4.0, and the terms forbid asserting proprietary rights over any part of the database); (e) a sentence in this spirit: "Registry data from ClinicalTrials.gov, a database of the U.S. National Library of Medicine. This lab is independent of the registry and of the U.S. Government; the grouping and counts are the lab's own." (The registry's term is that the data must not be represented as anything other than a United States Government database; the first draft of this proposal had it backwards.) "Current at all times" cannot be met by a frozen snapshot, and the terms also say to check the registry frequently. So: every NCT id links to the live record; a standing line says "Registry records change; the live record on ClinicalTrials.gov is current, this page is not"; the page states its snapshot date prominently and the maintainer names a cadence or an age after which the page is marked stale or withdrawn (a scheduled run is a human decision under the evidence skill's rules; the lab's default is never more often than hourly for one source). Quotes are clipped to what each count needs, because some registry text may belong to third parties. The manifest carries one line that the terms apply for as long as the data are kept. The registry's no-warranty statement is repeated on the method page as a courtesy.

## The page (design)

Same family as the Resources page and the map: static, generated, no script, no third-party request, accessible; the site is dark only today, so a light print stylesheet is the only light variant.

Top to bottom: headline and plain subhead; a ledger line in monospace (snapshot date, short hash, study count, the query as a link, which taggers ran, the hand-check result); two links ("Download the data", "How this was made"); a visible "What this does not say" box above any chart; three jump links ("I design or review trials", "I read trial papers", "I live with CF or care for someone"); Figure 1, the lit grid (endpoint class by start period); Figure 2, phase by class, in the same visual grammar; a real data table under each figure; "What each measure means" (one plain line per class, checked against `cf-research-context`); a five-step method strip; downloads and limits.

Figure 1: rows are classes in a fixed taxonomy order (never sorted by count), grouped under plain headings with "other" and "not stated" at the foot, equal in weight. Columns are start years on wide screens and five-year bins on phones (the generator writes both tiers; a container query picks one, as the map does). Every position starts as a faint unlit dot; a count lights a cyan circle with area proportional to the count and the numeral printed beside it; fewer than five is an open ring with the numeral and a legend line ("a few, not a trend"); zero is unlit and labelled "none in this snapshot", which is different from missing. One hue means "count" and nothing else is coloured; ring versus fill and the numerals carry the information, so it never relies on colour alone and survives forced-colours mode. The current year is hatched ("part year, to snapshot date"); early years carry a note that registration was not routinely required before about 2005 (from memory, to verify). A thin right column gives the true number of trials that year, all classes. Each SVG has a title and description in plain language, the data table sits right beneath it, cell numerals are links to the class page, and tap targets are 44 px.

CSS-only interaction: a switch between the two figures (two radios and `:has()`, both shown stacked where `:has()` is missing); phase and status filters on the class pages; a "showing N of M" line from a CSS counter, which must be checked in a browser against the script's count because it is a browser-computed number. Left out: filters that recompute aggregates, search, hover tooltips, animation, sort by count, percentages, trend arrows, "top endpoint" badges and any good-or-bad colouring.

Tone, in the lab's voice (to be reviewed by the maintainer and by a council before it ships). Headline: "What cystic fibrosis trials register as their main outcomes" (a trial can register several). Subhead: "A count of the main outcomes that trials testing a treatment or other intervention entered in ClinicalTrials.gov, grouped by what they measure. Taken from one dated copy of one registry, with the exact words behind every number." What this does not say: it counts what trial teams wrote down, not what trials found, and a measure that appears often is not a better measure; it says nothing about any treatment, any person's care or whether someone could join a trial (for that, talk with a CF care team; research, not medical advice, and not a replacement for clinical care); it covers one registry only, so trials registered elsewhere are not counted; the teams running each trial write these entries themselves, some are brief or unclear, the lab grouped them by stated rules and checked a sample by hand, and some will be misplaced.

A Spanish version is a separate page with `hreflang`, in Mexican Spanish, reviewed by the maintainer. Page text, class names, captions and glosses are translated; registry quotes, NCT ids, sponsor names and instrument names (CFQ-R and so on) stay as written.

## What it must not claim

Which endpoint is better, more sensitive, validated or accepted by regulators; whether any trial met its endpoint or any intervention works (results are a separate section); whether a trial switched its primary outcome (a snapshot holds current text); anything about a person's eligibility or care; "all CF trials in the world" (one registry only; EU, ISRCTN and other registries are absent). Three traps and their guards: frequency read as merit (no ranking words, a standing line in every caption); trends that are artefacts of registration rules and retrospective registration (counts not percentages, sparse years shaded, eras banded); clustering (separate study and entry views, open-label extensions flagged, a "CF only" toggle, a count deduplicated by lead sponsor beside the raw one).

## Build order

1. **Research repository, offline (built in #35, three blind reviews, never run against the registry).** A paged fetcher on the evidence client's rules (catalog gate, 1 request per second, request budget, honest user agent, records `dataTimestamp`, checks the response's `totalCount` against the records received, saves the pages and a hash manifest); the lexicon and the tagger; the checker (recomputes every committed count, rejects any quote that is not a substring, prints the metrics, fails a perturbed fixture); the labelling sheet for the frozen set; tests on synthetic responses. No network in the tests.
2. **Before any real fetch: fix the catalog entry.** Point `terms_url` at the Terms and Conditions page, and record the maintainer's decision on `redistribute` (committing registry text under the research repository's licence needs decision 7(d)). This is a change to `sources/catalog.yaml`, so it is its own reviewed pull request.
3. **The first real snapshot and the count of studies.** Needs a person's approval for the network call and a contact address for the user agent. The evidence client treats a contact as optional (R7) and checks it is a plain email when given (R11); the atlas fetcher requires one, read at run time from `EVIDENCE_CONTACT` and never stored. The lab's own address policy is T-0117.
4. **The person labels the 50 rows.** Human only.
5. **Taggers run, a challenger reviews a sample blind, metrics are printed.** Publication gate as in decision 5.
6. **A clinician reader for the plain-language glosses (T-0105).** The class names and the "What each measure means" lines are scientific copy on a public site and need a person's review (T3) first; until then the page ships class names without glosses.
7. **The site.** A generator that reads a pinned snapshot with a lock file, as the Evidence and Resources pages do; the page, the class pages and the downloads (with the items in decision 7); Playwright review (phone width, scripts off, forced colours, the browser-computed counter), then a council, then the maintainer's own review and merge.
8. **Later.** The Spanish page; an opt-in refresh schedule.
